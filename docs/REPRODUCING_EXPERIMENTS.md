# Reproducing the five v16 experiments

The root command `rerun_frozen.py` evaluates the recorded model-generated plans on the original analysis tables. It does not use saved estimates to calculate new estimates.

1. Install Python 3.12 and `requirements-analysis.txt` in a virtual environment.
2. Obtain the source data using `DATA_ACCESS.md`. For the validated HRS example, prepare `external_data/P02/data.csv`.
3. From the repository root, run:

```sh
python rerun_frozen.py --data-root external_data --case P02 --check-only
python rerun_frozen.py --data-root external_data --case P02 --output rerun_hrs --jobs 8
```

To select a different study:

```sh
python rerun_frozen.py --data-root external_data --case P03 --output rerun_P03
```

To execute all five studies, prepare all five tables, omit `--case`, and choose a fresh output directory. The full batch was not rerun to completion for this packaging revision; the completed HRS check is recorded in `VALIDATION.md`.

Alternatively, `--inputs local_inputs.json` accepts a JSON object mapping case IDs to CSV paths. Relative paths are resolved relative to that local manifest. Keep this machine-specific file outside version control.

## Execution

For each study the runner checks the data and accepted implementation hashes, serializes the original frozen specifications, and stages a separate runtime. It uses Boba 1.1.2 to compile and run each path. The portable runner batches up to 16 frozen paths per Boba script to avoid repeated interpreter startup. Each path still calls the original worker and produces its own receipt; this does not change the specification choices or plot groups. Use `--batch-size 1` for one official Boba script per path. The compiler bindings are flattened and checked against every frozen specification ID.

The original workers validate the input locks, effect and inference contracts and restrict analysis access to the staged data/runtime and installed libraries. These Python-level controls are not an operating-system security boundary. The worker environment excludes API credentials.

The accepted `analysis.py` files and both workers are unchanged. The newly generated Boba template substitutes only the portable runtime location and frozen specification ID. The templates originally used for v16 remain in each case directory for inspection. Recorded plans are loaded as literal assignments, not regenerated by a model.

Each study produces execution receipts and direction/significance summaries. After every selected study finishes, the controller opens the reference CSV and compares path status, options, effects, intervals, P values, and significance flags. Comparison tolerances are rtol=1e-9 and atol=1e-12; exact numeric equality is reported separately. The reference values are never passed to the scientific worker.

## Outputs

- `recomputed_results.csv`: newly calculated point estimates, inference fields, and choices.
- `recomputed_paths.json`: classified new results.
- `Pxx/evaluation.json`: direction and valid-test significance summaries by the frozen research-question groups.
- `Pxx/execution_results.json`: actual worker receipts, including failures.
- `figures/`: eight curves drawn from the new results, not the reference CSV.
- `reanalysis_report.json`: input/code fingerprints, environment, execution counts, and comparisons.

The HRS example produces 126 successful receipts, 90 valid P values, and 36 unavailable P values. For a full five-study run, the original v16 reference contains 504 receipts: 480 successful estimates, 24 failed paths, 372 valid P values, and 108 unavailable P values. NLSY imputation paths fail because the frozen implementation did not specify a donor-count parameter. These are retained; this artifact does not repair scientific choices to obtain a cleaner result.

Author-reference matching is separate. This command recomputes effect-direction and significance summaries; it does not re-extract author claims or rerun the v16 matching model. The published author-comparison summaries remain in `data/question_results.csv`; the matching and evaluation implementations are under `prototype/src/decision_option_lab/`.

Use a new output directory for every attempt. `--check-only` checks the supplied table/code identity without running Boba. `--font "DejaVu Sans"` selects a portable font. Figure typography may differ across platforms; the recorded full reanalysis was performed on Windows. No original observations are written into the repository's frozen data or reference directories.
